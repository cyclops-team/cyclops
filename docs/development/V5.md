# v5: addressing

The v4 line made the workspace's controls visible. v5 is about the other
half of the product: getting a message to an agent without leaving the
pane you are already in.

## The ask

Two requests, one subject:

- `@agent` in the terminal. Address an agent by name the way you address
  a person in a chat tool.
- Agents sending to each other with less ceremony than
  `cyclops send <label> --subject "..." --body "..."`.

## What exists today

`cyclops send` is the only door. It is a good door: the daemon gates on
the recipient's state, verifies the composer, and returns a receipt
carrying an evidence tier (`docs/guides/send.md`). Nothing about the
delivery pipeline is in question here. What is in question is the
ceremony between deciding to say something and it being said.

## Open questions

Scope is not decided. These are the decisions that gate any code:

1. Where `@agent` is typed. A shell pane's keystrokes belong to the
   process running in it, so Cyclops watching for a leading `@` means
   deciding what happens when that process is vim.
2. Whether `@agent` is a Cyclops surface or a shell surface. A workspace
   composer and a shell function are different products with different
   failure modes.
3. What a message with no `--subject` is. Every record line today
   carries one, and `cyclops history` is folded around that.
4. Whether the sender's identity still comes from the socket peer. It
   must. The header is unforgeable by design and nothing here changes
   that.

Decisions land in this file as they are made.
