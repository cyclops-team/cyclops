# v5: the admin is a participant

**Status:** Historical design record, not current implementation authority

v4 made the workspace's controls visible. v5 closes the hole underneath
them: Cyclops routes messages between agents well and leaves the human
out of its own messaging system. You cannot send from the workspace, the
reply address it hands every agent does not resolve, and anything an
agent sends you is a line in a stream you have to be watching.

## Where this came from

Four independent sources point at the same hole, which is why it is the
line rather than a list of tickets.

- Linear, Live Use Notes, marked BACKLOG: "We need make messages to the
  admin from the agents VISIBLE and like accessible because it can get
  easily lost when agents are messaging each other."
- The audit (2026-08-07): every non-`--fyi` message pastes
  `Reply: cyclops send admin --subject "..."`. `admin` is not a pane, so
  `resolve_recipient` returns `None`, the delivery is recorded
  `attention_required` with cause `no_such_pane`, and the eye opens. An
  agent that obeys the instruction Cyclops pasted into its own composer
  files a failed delivery.
- Wave C, carried since M8: `for_admin` plus `cyclops ack`.
- The operator's own ask: `@agent` in the terminal. The same gap that
  stops you receiving is what makes sending ceremony.

## What is in

Ranked by impact over effort. Efforts are the audit's, corrected by its
verifiers.

1. **`Ctrl+B` `@` opens a composer.** A modal the workspace owns, so
   every byte between the keypress and the daemon is ours and
   `@reviewer why is x*y broken?` arrives verbatim. Multi-day, and the
   days go to one thing: `daemon.rs` sets a 250ms IO deadline while
   `msg.send` blocks through paste-and-verify, so the send has to leave
   the render thread and report back through the notice.
2. **The admin inbox.** `for_admin`, a surface that holds rather than
   scrolls, and `cyclops ack` to clear it. This is Wave C and it is what
   the BACKLOG note above is asking for.
3. **A reply hint that is true.** Gate `render_payload` on
   `from != label::ADMIN`, the constant that already reserves the name.
   Hours of code, a day in total: it turns two committed gates red and
   stales three shipped captures in README, send.md and SKILL.md.
4. **`cyclops @target <free text>`** as the scripting primitive agents
   use. Hours. Not a positional body on `send`: a clap harness was built
   and run, and `send reviewer "ship it" --json` silently swallows
   `--json` into the body, `--fyi` likewise.
5. **Status detection, spike then fix.** GitHub issue #7, the only open
   issue on the repo, and the one Live Use Notes item still marked NOT
   ADDRESSED. See the hypothesis below.

Riding along because it is cheap and real, though it is not the theme:

- **A closing pane wedges its worker forever.** `await_ack`'s
  `recv_pane` arm has no `PaneRemoved` case, so the clock freezes,
  `worker.busy` stays true, and everything queued behind that pane is
  stranded until a daemon restart. INVARIANTS.md says limbo is a bug,
  and the two neighbouring loops handle the same event correctly. Hours.

## The status hypothesis, not yet a conclusion

`STATUS.md` names Codex confirmed wrong and Cursor suspected. The audit
separately found `marker_in_composer` reads only `line_regex` while
Codex and Cursor ship escaped-only rules, so it returns false
unconditionally for exactly those two CLIs.

Same two CLIs, same manifest rule family. That is suggestive, not
proven: `STATUS.md` calls the status problem "a detection / fusion gap,
not a delivery bug," so the two paths may not share code at all. Spike
it before scoping the fix. If they do share the escaped-rule handling,
one change closes issue #7 and the audit finding together.
