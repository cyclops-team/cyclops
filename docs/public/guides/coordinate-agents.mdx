title: "Coordinate agents"
description: "Send work, broadcast announcements, wait for turns, and review the record."
---

## Send one agent a request

```bash
cyclops send reviewer --subject "Review the last commit" --body "Check correctness and test coverage."
```

Cyclops durably accepts the message before returning. It then queues a
content-free wake for the recipient pane. The receipt keeps those facts
separate: `accepted` covers the mailbox record, while `wake <state>` reports
the current notification attempt.

The recipient retrieves the body only by claiming the exact id named by the
wake:

```bash
cyclops inbox list
cyclops inbox claim <message-id>
cyclops reply <message-id> --body "Reviewed. One issue."
```

The wake is one-shot. An ambiguous terminal outcome raises one attention item
and leaves the message claimable. Do not resend or requeue blindly. Follow
[Recover a notification](/guides/recovery) for inspection, guarded completion
or discard, and provably pre-write withdrawal.

## Broadcast

```bash
cyclops send --all --subject "Standup in 5" --fyi
```

A broadcast creates one immutable message with one mailbox entry and one wake
state per recipient. `--all` targets adopted agents, not the admin inbox.

## Wait for pane activity

```bash
cyclops wait reviewer --until done --timeout 2m
```

`done` means the working-to-idle edge for the same pane occupant. If the
process in the pane changes while waiting, Cyclops exits separately rather
than claiming the new process finished the old turn. This observes pane
activity and does not prove a specific message or task was completed.

## Watch live

```bash
cyclops watch
cyclops watch --with reviewer
```

The stream is calm by default and can switch to a firehose of every message
and state event. A bare `cyclops` opens the larger workspace interface with
the same event record beside live pane canvases.

## Read the record

```bash
cyclops history --with reviewer --limit 20
cyclops thread m-3f9c2a
```

The workspace message journal is append-only. `history` applies caller-scoped
visibility to the durable conversation. `messages` is the body-free view of
mailbox and wake state:

```bash
cyclops messages
```

Cyclops does not currently implement a `pipe` command or a `send --from`
shortcut. Put the relevant context in `--body`, pipe it through
`--body-file -`, or send a file's contents with `--body-file <path>`.
